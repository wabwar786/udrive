# Security posture and known limitations

Last reviewed at the first public-release audit. If you change anything in this
list, change it here in the same commit — a security document that has drifted
is worse than none, because somebody will plan around it.

## Implemented

- OTP values are stored as HMAC hashes, not plaintext.
- Refresh tokens are random and stored as hashes; access tokens are short-lived
  and refresh tokens rotate.
- Token versioning invalidates stale access tokens after approval, suspension or
  rejection.
- CNIC and licence identifiers are stored as keyed hashes with masked display
  values.
- Verification evidence is never served as a static file. Every read goes
  through an authorised endpoint, and the anonymous endpoints
  (`PublicVehicleImageController`, `CatalogController`) run with
  `allowLegacyFallback: false`, so a filename alone cannot be used to walk the
  storage roots.
- Uploads validate extension, size and file signature; paths are generated by
  the server and are traversal-safe.
- Admin and Operations endpoints are role-gated; approval prerequisites are
  enforced on the server, not in the portal.
- Rate limiting is in place per partition: 300 req/min globally, 40/min for
  location writes, 60/min for public tracking and 8/min on the OTP endpoints.
- Android cleartext HTTP is disabled.
- In Production, the fixed development OTP is not issued at all:
  `OtpDeliveryService.PlanAsync` returns an `Unavailable` plan and `AuthService`
  refuses the login with 503 rather than falling back to a known code. The only
  number that bypasses a live provider is the Play reviewer account seeded by
  migration 054.
- Account deletion is self-service from Settings and removes name, number and
  identity-document data server-side, closes all sessions and frees the number
  for re-registration.
- Privacy Policy and Terms are bundled in the app, served at `/privacy` and
  `/terms`, and linked from the login screen and Settings.
- `ProductionConfigurationValidator` checks the production secrets at start-up
  and, with `ENFORCE_PRODUCTION_SECURITY=true`, refuses to boot without them.

## Not implemented — accepted for this release

- **Admin portal sessions are bearer tokens in browser storage, not HttpOnly
  cookies, and there is no admin MFA.** This is the largest single gap. An admin
  account is protected by its password alone. Use a long unique password, keep
  the admin count small, and treat MFA as the next security task.
- **Uploaded files are not malware-scanned.** They are validated by signature
  and never executed or served from a web root, which limits but does not remove
  the risk.
- **Verification evidence sits on the server's own disk** (`UPLOAD_ROOT`, which
  must point at a mounted volume), not in private object storage with signed
  URLs. Anyone with host access can read it; the application layer cannot.
- **No penetration test and no external legal review** has been done against the
  live identity-document flow.
- **No automated cleanup job** for expired sessions and used OTP rows, and no
  alert on refresh-token reuse. Both are detectable only by looking.

## Operational requirements

Real CNIC and licence documents are collected the moment the app is public, so
before the first production rollout:

1. Set `ENFORCE_PRODUCTION_SECURITY=true` together with every production secret.
2. Set `UPLOAD_ROOT` to a mounted persistent volume. On ephemeral storage the
   verification documents are lost on every deploy, and a driver who was
   approved becomes unverifiable.
3. Turn on a live WhatsApp OTP provider in the admin portal and confirm the
   status line reads *Login codes: WhatsApp — live*. Without it, production
   logins are refused by design.
4. Rotate the Play reviewer code once review has passed. It is a constant in the
   shipped APK and it belongs to a real approved driver account.
